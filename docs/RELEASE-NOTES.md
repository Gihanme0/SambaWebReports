# Release Notes Template

Use this structure when preparing a release.

## Version

`vX.Y.Z`

## Date

`YYYY-MM-DD`

## Added

- New reports, filters, exports, or documentation.

## Changed

- Behavior, layout, workflow, or compatibility changes.

## Fixed

- Data accuracy, UI, export, or runtime fixes.

## Known Issues

- Verified limitations that users or maintainers should know before deployment.

## Upgrade/Test Notes

- PHP syntax checks required.
- Local report URLs to test.
- Database assumptions to re-verify.
- Export and print checks required.

Do not invent completed features in release notes. Link notes to actual commits, tested behavior, or verified requirements.
